# Постоянная публикация QA

Вход для другого чата: [QA_LATEST.md](../QA_LATEST.md), а для автоматического чтения — [QA_LATEST.json](../QA_LATEST.json). Каждый asset имеет прямой публичный HTTPS URL.

`qa-publication.yml` запускается автоматически после завершения Blender или WebGL workflow на main этого публичного репозитория. Он не выполняет код из артефактов; публикует только белый список моделей, исходников, кадров, MP4 и очищенных отчётов. Логи, браузерные профили, токены и параметры авторизации не публикуются. GitHub token берётся только из окружения Actions.

Для каждого run ID / attempt / commit создаётся отдельный prerelease. Это материал для художественной оценки, а не утверждённое качество. Старые опубликованные assets никогда не загружаются с `--clobber`, tag не перемещается. `build.json` и `SHA256SUMS.txt` фиксируют происхождение и контрольные суммы; записи `qa-results/qa-*.json` сохраняются в Git истории. Доступ каждого опубликованного файла проверяется без Authorization и cookies. Все ошибки публикации останавливают workflow, индекс не объявляет несуществующие ссылки успешными.

Индекс отдельно показывает последнюю попытку, последний успешный тест сцены и связанную сборку Blender. Если GLB захвачены из настоящих HTTP-ответов тестируемой сцены, связь с Blender подтверждается SHA256. Старые запуски без такого захвата имеют явно обозначенную историческую связь. Успех QA и художественное утверждение — разные статусы.

Текущая сцена изменяема. `?v=` не является immutable deployment. Для анализа старой версии используйте конкретный Release и его файлы; никогда не выдавайте текущую сцену за старое доказательство.

Перед публикацией новой версии тестовой сцены обновить `publication/config.json`: URL, source commit сайта, версию и ожидаемую модель. Затем выполнить Blender и WebGL workflow. При завершении каждой значимой доработки проверить publication workflow, реальные кадры, публичные скачивания и индекс. В конце ответа дать ссылку на актуальный индекс и на конкретную проверенную сборку.

Для восстановления пропущенного запуска есть `workflow_dispatch` с точным `run_id`. Если Actions Artifact истёк до публикации, успешные исторические доказательства не генерируются заново под прежним tag: публикация останавливается. Повторный тест получает отдельный run/attempt и собственную запись.

Для принятых пользователем материалов художественный статус в следующей публикации меняется только по явному подтверждению. Автоматически все новые результаты имеют PENDING_USER_REVIEW.

Release tag привязан к коммиту публикации на main: Actions token не может ставить tag на исторический commit с отличающимися workflow. Это не замена исходной сборки. `commit_sha` всегда обозначает проверенные исходники; `publication_commit` — момент публикации. Ссылка `tested_source_archive_url` даёт именно архив проверенного commit. Исторические assets копируются из точного исходного run и не генерируются заново.

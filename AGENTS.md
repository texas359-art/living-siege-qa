# Правила разработки и передачи результатов

- Работать только с texas359-art/living-siege-qa и тестовой сценой существующей игры. Основную игру не заменять до отдельного утверждения пользователя.
- Не предлагать нанимать художников/программистов и не подменять создание ассета концепцией или ТЗ. Использовать Blender bpy и бесплатную существующую инфраструктуру; при сбое исследовать другие технические способы.
- После существенного изменения персонажа выполнить Blender экспорт, настоящий WebGL-тест опубликованной сцены, снять реальные кадры и видео, самостоятельно просмотреть результат и исправить дефекты. Наличие клипов и PASS не заменяет художественную оценку.
- При публикации новой тестовой сцены обновить publication/config.json с её URL и source commit. Не выдавать изменяемый URL сайта за замороженное историческое доказательство.
- Дождаться успешного qa-publication.yml. Убедиться, что QA_LATEST.md / QA_LATEST.json обновлены, Release assets доступны без авторизации, сохранены run ID, attempt, точный tested commit, дата, статусы и контрольные суммы.
- Сохранять файлы каждого запуска отдельно в Releases. Не перемещать tags, не использовать --clobber, не заменять старые доказательства новой сборкой. Не публиковать токены, приватные данные, browser profiles и полные логи.
- Различать живую запись SwiftShader и покадровый WebGL-рендер. Не утверждать аппаратный FPS или качество Clash Royale по покадровой записи.
- В конце каждого ответа давать актуальный индекс и конкретную проверенную сборку: https://github.com/texas359-art/living-siege-qa/blob/main/QA_LATEST.md и её точный Release URL.

Публичная точка входа другого чата: QA_LATEST.md; машиночитаемые ссылки и происхождение — QA_LATEST.json. Материалы для художественной оценки не требуют ручной пересылки между чатами.
